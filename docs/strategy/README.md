### 승률 수치를 비교하기 전에

**v1~v5의 종합 승률과 v6~v7의 "공통 풀" 수치는 서로 다른 프로토콜로 잰 값이다.**
v6에서 소표본에 속아 회귀를 두 번 겪은 뒤 측정 방식을 바꿨다 ([v6 문서](v6.md) 참고):

> 상대 풀 종합(지터 {0,8} × 시드 24개 × 양 진영, 상대당 48게임)이 아니면 믿지 말 것.
> 소표본 단일 조건 수치는 **±20%p씩 튄다.**

그리고 **"풀 평균"의 모집단이 버전마다 다르다.** v5·v6의 평균은 AI·v1~v4 **5종**이고,
v7의 82.9%는 거기에 v5·v6을 더한 **7종**이다. 위 표의 "공통 풀"은 전부 AI·v1~v4
5종으로 맞춘 값이라 그대로 비교해도 된다.

| | 공통 풀 (AI·v1~v4) | 집안 맞대결 |
|---|---|---|
| v5 | 90.2% | — |
| v6 | 92.6% | vs v5 **50%** (동전던지기) |

**v7의 가치는 외부 상대 성적이 아니라 집안 맞대결이다.** v6까지는 집안끼리 붙으면

## 용어 — `lag`와 `LAG_FRAMES`는 다른 것이다

문서 곳곳에 "지연"이 나오는데 **서로 다른 두 가지**다. 헷갈리기 쉬우니 여기서 못 박는다.

| | 무엇 | 정하는 곳 | 값 |
|---|---|---|---|
| `applyLag` (lag1/2/3) | **환경의 실제 지연** | 하네스 | 브라우저 실측 = **1** |
| `LAG_FRAMES` | **봇이 믿는 지연** | 봇 코드 | **2** (고정) |

### `applyLag` — 환경이 얼마나 느린가

브라우저의 Worker 왕복을 하네스가 흉내내는 값. `decide()`가 반환한 조작이 **몇 프레임
뒤에 실제로 적용되는가**를 정한다 (`arena/arena.mjs`).

```js
this.pending = { action, readyAt: frame + this.applyLag };
```

`decide`는 3프레임마다 호출되지만 결과가 즉시 반영되지는 않는다. `applyLag` 프레임이
지나야 `latest`로 넘어가고, 그 전까지 매 프레임 적용되는 건 **직전에 도착한 낡은 조작**이다.

```
applyLag = 1              applyLag = 2
frame 0  decide 호출      frame 0  decide 호출
frame 1  ← 반영           frame 1  (아직 옛 조작)
frame 2                   frame 2  ← 반영
```

`arena/bench.mjs`가 `LAGS = [1, 2, 3]`을 전부 훑어 `lag1: 75% (10-3)` 같은 칸으로 출력한다.
즉 **lag1/lag2/lag3은 세 가지 서로 다른 환경에서 각각 잰 승률**이지 하나의 수치가 아니다.

**브라우저 실측값은 1이다.** `pendingRequestId` 전이를 직접 계측했다 — Worker 응답은
요청을 보낸 프레임의 **다음 프레임** `getInput` 전에 도착한다.
lag2·lag3은 "환경이 더 나쁘면?"을 보는 **강건성 테스트**다.

### `LAG_FRAMES` — 봇이 스스로 가정하는 지연

봇 코드 안의 튜닝 파라미터. 계획을 세울 때 "지금부터 n프레임은 내 입력이 안 먹힌다"고
믿는 값이다. 점프 타이밍 역산에서 `jumpAt < lag`면 "이미 늦었다"고 판단하는 그 lag.

**실제(1)와 가정(2)이 일부러 다르다.** 조금 일찍 움직이는 쪽이 늦어서 공을 놓치는 것보다
낫기 때문이다. 지연 1/2/3 전 구간에서 각각 100/100/94%로 가장 강건했던 값이 2였다.

### 왜 이 구분이 중요한가

v4의 `CONTACT_GAIN`, v5의 `DEF_GROUND_TRUST` 같은 파라미터는 **`applyLag`에 따라 최적값이
뒤집힌다.** 둘 다 "미래를 예측해서 미리 결단한다"는 성격이라, 환경 지연이 커질수록
결단이 코트에 반영될 때쯤 이미 낡아 있고 되돌릴 시간도 없다.

| 파라미터 | lag1 (실측) | lag2~3 |
|---|---|---|
| `CONTACT_GAIN = 30` | v3 대비 75% | **36% — 무너진다** |
| `DEF_GROUND_TRUST = 1` | v3·v4 상대 100% | **약한 상대에게 21~25%** |

실측이 1이라 lag1 성능을 우선해 확정했다.
**대회 당일 반영 지연이 2로 보이면 v4로 내리거나 `DEF_PREDICT = 0`으로 되돌릴 것.**

## 측정 방법

```bash
node arena/bench.mjs          # 전 버전 × 전 상대 × lag 1/2/3 매트릭스
node arena/run.mjs <left> <right> [세트수] [applyLag]   # 단일 대전
```

봇을 고칠 때는 브라우저로 한 판씩 보지 말고 여기서 먼저 잰다.
성능표의 기본 조건은 **jitter=8, 24세트/칸**이다.
